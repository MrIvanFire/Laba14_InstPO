### Что сделали:

### 1. Реализовали JWT-авторизацию
   Создали модель User с полями Id, Email, PasswordHash, Name
   Добавили хэширование паролей через SHA256
   Создали эндпоинты `/api/auth/register` и `/api/auth/login`
   Генерируем JWT-токен с claims (Id, Email) при успешном входе

### 2. Защитили CRUD-маршруты
   POST/PUT/DELETE `/api/tasks` проверяют заголовок Authorization: Bearer <token>
   Валидируем JWT через JwtSecurityTokenHandler
   Без токена или с невалидным токеном → 401 Unauthorized

### 3. Добавили ручную валидацию
   Проверяем Title (обязательное, 1-200 символов)
   Проверяем Priority (от 1 до 5)
   Проверяем DueDate (не в прошлом)
   Проверяем Category (до 50 символов), Location (до 100 символов)
   Ошибки накапливаем в List<ValidationError> → 400 с JSON

### 4. Реализовали централизованную обработку исключений
   Обернули ProcessRequest в try-catch
   Логируем исключение с stack trace в консоль
   Возвращаем 500 с JSON `{ error: "InternalServerError", message: "..." }`

### 5. Выполнили Git-операции
   Создали ветку `feature/jwt-auth`
   Сделали push в удалённый репозиторий
   Сняли граф коммитов: `git log --oneline --graph --all -15`

   Провели эксперимент со stash (сохранение изменений при смене ветки)

### Что дало:
**Безопасность** - API недоступен без валидного JWT-токена

**Единый формат ошибок** - клиент получает одинаковую структуру JSON (400/401/404/500)

**Отказоустойчивость** - сервер не падает при исключениях, возвращает 500

**Ручной контроль** - в отличие от ASP.NET Core (middleware/атрибуты), всё реализовали вручную: проверка заголовка, валидация токена, обработка ошибок

**Контроль версий** - ветка изолирует фичу, stash позволяет переключаться без потери изменений
